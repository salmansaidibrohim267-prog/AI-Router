# Release — GitHub Release

Each version creates a GitHub Release with **all** supporting artifacts.

## What a release contains

| Asset | File | Generated by |
| --- | --- | --- |
| Release body | `CHANGELOG.md` | `ReleaseManager.write_changelog()` |
| Release notes | auto | `generate_release_notes: true` (softprops) |
| Signature | `dist/release/signature.json` | `sign_manifest()` |
| History | `dist/release/history.json` | `save_history()` |
| SBOM | `dist/release/sbom.spdx.json` | `anchore/sbom-action` |
| Changelog | `CHANGELOG.md` | pipeline |

## Tag & name

- Git tag: `v1.0.0`
- Release name: `1.0.0`
- `prerelease: true` when the version contains `-` (e.g. `1.0.1-rc.1`)

## Creating a release

Via `workflow_dispatch` (see `docs/release/release-process.md`) or manually:

```bash
git tag v1.0.0 && git push origin v1.0.0
# then create the release in the GitHub UI using release/RELEASE_NOTES_v1.0.0.md
```

The automated pipeline is the canonical path: it reuses `ReleaseManager` to
keep history and changelog consistent, and pushes the changelog commit back
to `main`.

## Editing policy

- Releases are **immutable**: tags and assets are never force-updated
- Fixes land as new patch releases, not rewrites
- `latest` is only advanced by the next release

## Verification after release

```bash
# assets present
curl -s https://api.github.com/repos/salmansaidibrohim267-prog/AI-Router/releases/latest | python3 -c "import json,sys; print([a['name'] for a in json.load(sys.stdin)['assets']])"
```
